# Обязательные меры по защите данных при передаче

1.  **Шифрование канала (TLS 1.3):** Весь трафик между мобильным приложением и API Gateway должен передаваться исключительно по протоколу HTTPS с использованием TLS версии не ниже 1.2 (приоритет 1.3) и стойких шифров. Использование незашифрованного HTTP строго запрещено.
2.  **Certificate Pinning (Закрепление сертификата):** В код мобильного приложения «зашивается» публичный ключ или хэш сертификата API Gateway. Это защищает от MITM-атак (Man-in-the-Middle), когда злоумышленник пытается подменить сервер с помощью самоподписанного сертификата.
3.  **Защита от SQL-инъекций (WAF и ORM):** На уровне API Gateway внедряется Web Application Firewall (WAF) для фильтрации вредоносных payload'ов. На уровне бэкенда (CRM/Расписание) — строгое использование ORM (например, Hibernate) и параметризованных запросов (решение проблемы INT-006).
4.  **Отсутствие чувствительных данных в логах:** API Gateway и BFF должны маскировать (заменять на `***`) заголовки `Authorization` и поля с персональными данными (ФИО, номера телефонов, результаты анализов) при записи в логи, чтобы исключить их утечку через системы мониторинга.
5.  **Минимизация данных (Data Minimization):** Передавать в мобильное приложение только те данные, которые необходимы для конкретного экрана (например, не отдавать полную историю болезни в ответ на запрос списка записей). 
6.  **Защита от подмены сессии:** Использование короткоживущих JWT (15 минут) и привязка Refresh Token к конкретному устройству (Device ID). При обнаружении аномалий (например, запрос с другого гео) все токены пользователя отзываются (решение проблемы SD-007).
