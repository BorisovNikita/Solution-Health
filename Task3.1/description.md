## Концепция решения

Для доставки результатов анализов используется **Apache Kafka** в роли надёжного буфера между LIS и остальной системой.

**Поток данных:**

1. LIS сохраняет результат в своей базе и фиксирует задачу на отправку.
2. Фоновый процесс LIS гарантированно отправляет данные в Kafka. Если сеть упала — данные остаются в базе и будут отправлены повторно.
3. Kafka хранит сообщения. Если CRM или Сервис уведомлений временно недоступны, они прочитают данные позже, когда восстановятся.
4. CRM обновляет карточку пациента и отдаёт данные в мобильное приложение по API.
5. Сервис уведомлений отправляет push-сигнал пациенту, приложение забирает данные из CRM.

## Сравнение Kafka и RabbitMQ

|Критерий|Apache Kafka (Выбрано)|RabbitMQ|Обоснование|
|-|-|-|-|
|**Гарантия доставки**|Высокая (хранение на диске)|Средняя (удаление после прочтения)|Kafka не теряет данные при падении CRM.|
|**Повторное чтение**|Есть|Нет|Позволяет перечитать данные после сбоев.|
|**Пиковая нагрузка**|Высокая (сглаживает всплески)|Низкая (падает при переполнении)|Решает проблему SD-006 (падение уведомлений).|
|**Порядок данных**|Сохраняется|Ограничен|Важно для хронологии анализов.|
